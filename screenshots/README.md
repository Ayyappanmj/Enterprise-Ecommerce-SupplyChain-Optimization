# Screenshots

There is no Power BI `.pbix` file in this repo (see Phase 8 — Power BI Desktop
is Windows-only GUI software and wasn't available in the build environment),
so these aren't dashboard screenshots. They're real matplotlib charts,
generated by querying the actual SQLite warehouse built in Phase 6, from a
full-scale run (500K orders, 1.5M sales lines, 445K shipments, 75K returns).
Regenerate anytime with a few lines of pandas + matplotlib against
`data/warehouse/warehouse.db`.

| File | Shows |
|---|---|
| `01_monthly_revenue_margin_trend.png` | Monthly revenue (bars) and gross margin % (line) over the full 3-year window |
| `02_top_countries_by_profit.png` | Top 10 countries by gross profit |
| `03_shipping_delay_distribution.png` | Shipment count by delay bucket |
| `04_return_reasons.png` | Refund dollars by return reason |
| `05_warehouse_volume_vs_delay.png` | Every warehouse's shipment volume vs. average delay |

## Read these with the right expectation

The underlying data is synthetic (Phase 1), and in several places that shows
up directly in the shape of these charts — flagged here rather than left for
someone to discover and wonder if it's a bug:

- **Chart 2** (top countries): all 10 bars are within about 5% of each other.
  Phase 1 assigns no real per-country demand signal, so country-level revenue
  is close to uniform by construction. A real dataset would show more spread.
- **Chart 3** (delay distribution): "Severe (15d+)" is exactly zero, because
  Phase 1's delay model (`src/data_generation/generate_inventory_shipping.py`)
  draws delayed shipments from **1–14 days** — 15+ day delays simply aren't in
  the generator's range, not a quirk of the chart.
- **Chart 4** (return reasons): all 7 reasons cluster within about 8% of each
  other, because Phase 1 assigns a reason uniformly at random rather than
  weighting it by product or return type.
- **Chart 5** (warehouse volume vs. delay): volume clusters into a handful of
  discrete vertical bands. That's a real structural property of the data (150
  warehouses draw from a shared pool of shipping routes with a small number of
  distinct transit-time/volume profiles), not a plotting artifact.

None of this is a defect in the charts or the SQL behind them — it's a
reminder that this is a demonstration pipeline built on synthetic data, and
the charts honestly show what that data looks like rather than a prettier,
hand-picked version of it.
