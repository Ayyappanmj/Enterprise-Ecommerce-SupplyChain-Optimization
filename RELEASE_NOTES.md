# Release Notes

One entry per git tag. Each tag corresponds to one phase of the build — see
[CHANGELOG.md](CHANGELOG.md) for the full detail behind any entry here.

## v0.12.0 — GitHub Packaging

MIT `LICENSE`, an expanded `.gitignore` (coverage artifacts, `node_modules`,
CSV exports), this file, and `GITHUB_SETUP.md` (suggested repo
description/topics, plus an explicit note on what the commit history is and
isn't — real commits with real diffs, made in one assembly session, not a
simulated multi-week timeline).

## v0.11.0 — Documentation

Rewrote README.md as a proper top-level project doc (Problem Statement,
Architecture, Tech Stack, Screenshots, Results/KPIs, Business Impact, Folder
Guide, Installation, Known Limitations, Future Improvements), moved the
detailed phase-by-phase build log to CHANGELOG.md, and added 5 real
matplotlib charts (`screenshots/`) generated by querying the actual
warehouse — no Power BI file exists, so these are an honest substitute, not
a placeholder for something that doesn't exist.

## v0.10.0 — Testing

71 unit tests (`tests/`), 98.7% line coverage, 0 failures. Found and fixed a
real `ZeroDivisionError` bug in margin calculation caused by a pandas
dtype-contamination edge case. `pytest`/`coverage.py` couldn't be installed
(no network access), so tests are `unittest.TestCase`-based (pytest runs
these natively) and coverage was measured with the stdlib `trace` module.

## v0.9.0 — Architecture Diagrams

5 diagrams (ETL Flow, Cloud Architecture, Warehouse Star Schema, Dashboard
Flow, Git Workflow) in `architecture/`, as Mermaid source + rendered SVG/PNG.
Actually rendered and visually inspected via `mermaid-cli`.

## v0.8.0 — Power BI Dashboard Design

DAX measures (`dashboards/dax_measures.dax`) and a full build guide
(`dashboards/README.md`) for a 6-page executive dashboard. Every headline
measure's expected value was checked against the real warehouse in SQL first.
No Power BI Desktop was available to open/verify the file itself (Windows-only
software). Found and fixed a real schema gap while designing this: `FactReturns`
had no country/warehouse key, so a "return rate by country" measure would have
silently shown the same number for every country.

## v0.7.0 — Advanced SQL

120 analytical queries (`sql/window_queries.sql` + `sql/business_queries.sql`)
plus 10 views (`sql/views.sql`), all executed against the real warehouse.
Covers window functions, CTEs, 2 recursive CTEs, and the project's named
business questions (worst warehouse, slowest country, highest-margin
products, return hotspots, monthly retention). `sql/procedures.sql` (MySQL
stored procedures/functions/triggers) is written but never executed — SQLite
has no equivalent feature to test it against.

## v0.6.0 — MySQL Data Warehouse

Kimball star schema: 5 dimensions + 3 facts (`sql/schema.sql`,
`src/warehouse/`). Loaded and verified at full scale (1.5M+ `FactSales` rows,
zero orphaned foreign keys) against SQLite, since no MySQL server was
available. The dimensional-modeling logic is 100% shared between the SQLite
and MySQL loaders.

## v0.5.0 — Feature Engineering

Gross/net margin, CLV, AOV, repeat purchase rate, return rate, warehouse
utilization, profit by country (`src/feature_engineering/`). Found and fixed
a real data-generation bug this phase exposed: warehouse capacity was sized
far too small relative to generated inventory, producing 2,000%+ utilization
numbers; fixed at the source in Phase 1's generator.

## v0.4.0 — Data Cleaning

Deduplication, null handling, currency conversion, timezone normalization,
negative-value detection, impossible-date correction, and IQR-based outlier
flagging (`src/cleaning/`), with before/after reports. Verified by injecting
known-bad rows and confirming the cleaner catches exactly them.

## v0.3.0 — Cloud Storage

Upload pipeline for GCS, S3, and a zero-dependency local `dry_run` provider
(`src/cloud/`), sharing one interface and one bucket layout. Only `dry_run`
was tested end-to-end — no cloud credentials were available for the real
providers.

## v0.2.0 — ETL Pipeline

Multi-source ETL (`src/etl/`): a Web Orders CSV, an Inventory CSV, and a real
Flask mock Shipping API with injected failures, unified by incremental
watermark-based loading, retry-with-backoff, validation, and quarantine.
Verified live: watched a real retry recover from an injected 503, and
confirmed a second run loads only new rows.

## v0.1.0 — Enterprise Data Generation

Synthetic dataset generator (`src/data_generation/`): 15 tables, 500K orders,
50K customers, 10K products, 150 warehouses — fully offline, no API keys, no
Faker dependency. Full-scale generation runs in ~13 seconds.
